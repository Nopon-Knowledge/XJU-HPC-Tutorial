# 深度学习环境依赖配置教程

高算平台目前可以直接连接外网，因此不再需要在本地下载 wheel、压缩并上传安装包。Python、CUDA 运行环境和项目依赖都可以在高算平台终端中在线配置。

本教程依次介绍：

1. 选择并创建指定 Python 版本的独立环境；
2. 配置清华 Anaconda 和 PyPI 镜像；
3. 配置平台提供的 CUDA 12.1；
4. 安装与 CUDA 匹配的 PyTorch；
5. 安装项目的其他深度学习依赖；
6. 通过作业调度系统在 GPU 节点验证环境。

> 环境安装和依赖下载可以在登录节点终端完成，但不要在登录节点运行训练、推理、CUDA 测试或其他计算任务。计算任务必须使用 `jsub` 提交到计算节点。

## 1. 先确定项目需要的版本

配置环境前，应先查看项目的 `README.md`、`requirements.txt`、`pyproject.toml` 或环境配置文件，确定以下信息：

- Python 版本；
- 深度学习框架及版本，例如 PyTorch、TensorFlow；
- CUDA 版本；
- 其他依赖及版本。

不要直接把所有软件都安装为最新版。Python、PyTorch、CUDA 和其他依赖必须互相兼容。

平台当前实测可用的相关模块如下：

| 模块 | 提供的环境 | 适用场景 |
| --- | --- | --- |
| `python/3.8.10` | Python 3.8.10 | 运行明确要求 Python 3.8 的旧项目 |
| `anaconda/3` | Python 3.9.7、Conda 4.10.3 | 创建 Python 3.9 虚拟环境，或在线创建其他 Python 版本 |
| `cuda-12.1` | CUDA Toolkit 12.1 | 编译 CUDA 扩展或运行依赖系统 CUDA Toolkit 的程序 |

查看平台当前提供的模块：

```bash
module avail
```

查看某个模块会修改哪些环境变量：

```bash
module show anaconda/3
module show cuda-12.1
```

> `/usr/bin/python` 是系统 Python 2.7，不要用它创建深度学习环境。

## 2. 配置 Python 版本

每个项目都应使用独立环境。下面统一将环境安装在 `$HOME/venvs` 中，不要把虚拟环境提交到 Git 仓库。

### 2.1 推荐方式：用清华 Anaconda 源创建指定 Python 版本

这种方式可以直接在线选择 Python 3.10、3.11 等版本，不需要下载源码并手动编译。下面以 Python 3.10 为例。

先加载平台的 Anaconda：

```bash
module purge
module load anaconda/3
conda --version
```

设置环境路径：

```bash
ENV_DIR="$HOME/venvs/dl-py310-cu121"
```

通过清华 Anaconda 镜像创建 Python 3.10 环境：

```bash
conda create --yes \
  --prefix "$ENV_DIR" \
  --override-channels \
  --channel https://mirrors.tuna.tsinghua.edu.cn/anaconda/pkgs/main \
  python=3.10 pip
```

如果项目要求 Python 3.11，只需要同时修改环境名和 `python=` 后面的版本：

```bash
ENV_DIR="$HOME/venvs/dl-py311-cu121"

conda create --yes \
  --prefix "$ENV_DIR" \
  --override-channels \
  --channel https://mirrors.tuna.tsinghua.edu.cn/anaconda/pkgs/main \
  python=3.11 pip
```

初始化 Conda 的当前 Shell，然后激活环境：

```bash
source "$(conda info --base)/etc/profile.d/conda.sh"
conda activate "$ENV_DIR"
```

检查 Python 版本和路径：

```bash
which python
python --version
python -m pip --version
```

输出的 Python 路径应位于 `$HOME/venvs/dl-py310-cu121/bin` 中。

以后重新登录平台时，使用以下命令重新进入环境：

```bash
module load anaconda/3
source "$(conda info --base)/etc/profile.d/conda.sh"
conda activate "$HOME/venvs/dl-py310-cu121"
```

作业调度时不需要执行 `conda activate`，直接使用环境中 Python 的绝对路径更加可靠：

```text
$HOME/venvs/dl-py310-cu121/bin/python
```

清华 Anaconda 镜像的完整配置说明见[清华大学开源软件镜像站 Anaconda 使用帮助](https://mirrors.tuna.tsinghua.edu.cn/help/anaconda/)。

### 2.2 使用平台自带的 Python 3.9

如果项目支持 Python 3.9，可以直接基于平台的 Anaconda Python 3.9.7 创建轻量虚拟环境：

```bash
module purge
module load anaconda/3

ENV_DIR="$HOME/venvs/dl-py39"
python -m venv "$ENV_DIR"
source "$ENV_DIR/bin/activate"

which python
python --version
```

### 2.3 使用平台自带的 Python 3.8

仅当旧项目明确要求 Python 3.8 时使用：

```bash
module purge
module load python/3.8.10

ENV_DIR="$HOME/venvs/dl-py38"
python3 -m venv "$ENV_DIR"
source "$ENV_DIR/bin/activate"

which python
python --version
```

当前版本的部分深度学习框架已经不再支持 Python 3.8 或 3.9。新项目优先使用 Python 3.10 或项目官方推荐版本。Python 官方对 `venv` 的说明见[`venv` 文档](https://docs.python.org/3/library/venv.html)。

## 3. 配置清华 PyPI 镜像

激活目标环境后，后续统一使用 `python -m pip`。这样可以确保依赖安装到当前 Python 环境，而不是系统环境。

清华 PyPI 镜像地址为：

```text
https://pypi.tuna.tsinghua.edu.cn/simple
```

先临时使用清华镜像升级基础安装工具：

```bash
python -m pip install \
  -i https://pypi.tuna.tsinghua.edu.cn/simple \
  --upgrade pip setuptools wheel
```

将清华镜像设为 pip 默认源：

```bash
python -m pip config set \
  global.index-url \
  https://pypi.tuna.tsinghua.edu.cn/simple
```

检查配置：

```bash
python -m pip config get global.index-url
python -m pip config list
```

输出中应包含：

```text
https://pypi.tuna.tsinghua.edu.cn/simple
```

只想让某一次安装使用清华镜像时，可以直接使用 `-i`：

```bash
python -m pip install \
  -i https://pypi.tuna.tsinghua.edu.cn/simple \
  numpy
```

镜像地址必须使用 HTTPS，末尾的 `simple` 不能省略。详细说明见[清华大学开源软件镜像站 PyPI 使用帮助](https://mirrors.tuna.tsinghua.edu.cn/help/pypi/)。

## 4. 配置 CUDA

### 4.1 区分驱动、Toolkit 和框架 CUDA 运行时

配置 CUDA 时需要区分三个概念：

- **NVIDIA 驱动**：由平台管理员安装，普通用户不要安装或升级驱动；
- **CUDA Toolkit**：平台通过 `cuda-12.1` 模块提供，包含 `nvcc`、头文件和开发库；
- **PyTorch CUDA 运行时**：随 PyTorch CUDA wheel 及其依赖安装到 Python 环境中。

对大多数直接使用 PyTorch 的项目，不需要在个人目录重新安装完整 CUDA Toolkit。只有编译自定义 CUDA 扩展，或项目明确依赖 `nvcc` 时，才必须加载平台 CUDA 模块。

### 4.2 查看并加载平台 CUDA 12.1

```bash
module avail cuda
module load cuda-12.1
nvcc --version
```

平台的 CUDA 12.1 安装路径为：

```text
/storage/software/cuda-12.1
```

编译 CUDA 扩展时设置 `CUDA_HOME`：

```bash
module load cuda-12.1
export CUDA_HOME=/storage/software/cuda-12.1

echo "$CUDA_HOME"
command -v nvcc
nvcc --version
```

`module load cuda-12.1` 已经设置了 `PATH` 和 `LD_LIBRARY_PATH`，通常不需要手工重复添加这些目录。

### 4.3 在 GPU 计算节点查看驱动

登录节点没有分配 GPU，不能用登录节点的 `nvidia-smi` 判断 GPU 环境。应提交一个短作业：

```bash
mkdir -p "$HOME/logs"

jsub -q gpu -J nvidia-smi-check \
  -cwd "$HOME" \
  -o "$HOME/logs/nvidia-smi.%J.out" \
  -e "$HOME/logs/nvidia-smi.%J.err" \
  -n 1 -M 1024 \
  -gpgpu 1 \
  nvidia-smi
```

通过 `jjobs` 查看作业状态：

```bash
jjobs
```

作业结束后查看输出日志：

```bash
ls -lt "$HOME/logs" | head
```

`nvidia-smi` 顶部显示的 `CUDA Version` 是当前驱动支持的最高 CUDA 版本，不代表个人环境中已经安装了同版本 Toolkit。选择 PyTorch CUDA wheel 时，其 CUDA 版本不能超出节点驱动的兼容范围。CUDA 兼容原则可参考 [NVIDIA CUDA Compatibility](https://docs.nvidia.com/deploy/cuda-compatibility/)。

## 5. 安装与 CUDA 匹配的 PyTorch

### 5.1 先确定 PyTorch、Python 和 CUDA 的对应关系

安装前检查：

1. 项目是否固定了 PyTorch 版本；
2. 该 PyTorch 版本支持哪些 Python 版本；
3. 该 PyTorch 版本提供哪些 CUDA wheel；
4. GPU 节点驱动是否支持对应 CUDA 版本。

新项目应通过 [PyTorch Start Locally](https://pytorch.org/get-started/locally/) 选择 Linux、Pip、Python 和合适的 CUDA 版本。旧项目可在 [Previous PyTorch Versions](https://pytorch.org/get-started/previous-versions/) 中查找对应命令。

### 5.2 平台 CUDA 12.1 示例

下面使用与平台 CUDA 12.1 对应的 PyTorch 2.4.1 作为完整示例：

```bash
python -m pip install \
  torch==2.4.1 \
  torchvision==0.19.1 \
  torchaudio==2.4.1 \
  --index-url https://download.pytorch.org/whl/cu121
```

这里使用 PyTorch 官方 CUDA wheel 源，是因为 `cu121` 等 CUDA 专用 wheel 由 PyTorch 官方专用索引提供。清华 PyPI 镜像继续用于 NumPy、TensorBoard、OpenCV 等普通 PyPI 依赖。

如果项目要求其他 PyTorch 或 CUDA 版本，不要只替换 `cu121`，还必须同时核对 `torch`、`torchvision` 和 `torchaudio` 的版本组合。例如：

```text
cu118  表示 CUDA 11.8 wheel
cu121  表示 CUDA 12.1 wheel
cu124  表示 CUDA 12.4 wheel
cpu    表示仅 CPU wheel
```

实际可用选项随 PyTorch 版本变化，以 PyTorch 官方安装页面为准。

### 5.3 检查 PyTorch 安装结果

```bash
python -c "import torch; print('PyTorch:', torch.__version__); print('PyTorch CUDA:', torch.version.cuda)"
```

对于上面的 `cu121` 示例，`torch.version.cuda` 应显示 `12.1`。登录节点执行下面的命令返回 `False` 是正常现象，因为登录节点没有分配 GPU：

```bash
python -c "import torch; print(torch.cuda.is_available())"
```

是否真正可用必须在第 7 节的 GPU 作业中验证。

## 6. 安装其他深度学习依赖

### 6.1 优先安装项目自己的依赖文件

进入项目目录：

```bash
cd "$HOME/python_project/你的项目目录"
```

如果项目提供 `requirements.txt`：

```bash
python -m pip install \
  --timeout 120 \
  --retries 10 \
  -r requirements.txt
```

如果 `requirements.txt` 已经包含 PyTorch，应先确认其中的版本和下载源是否正确，避免覆盖第 5 节安装好的 CUDA 版本。

### 6.2 按需安装常用依赖

科学计算和数据处理：

```bash
python -m pip install numpy scipy pandas scikit-learn h5py
```

可视化和图像处理：

```bash
python -m pip install matplotlib seaborn pillow opencv-python-headless
```

训练辅助工具：

```bash
python -m pip install tqdm pyyaml einops tensorboard
```

Notebook 环境：

```bash
python -m pip install jupyterlab ipykernel
```

高算平台通常没有桌面显示环境，因此 OpenCV 推荐安装 `opencv-python-headless`，不要同时安装 `opencv-python` 和 `opencv-python-headless`。

这些命令只是示例。项目没有使用的包不需要安装，项目已经固定版本时应保留版本限制。例如：

```bash
python -m pip install "numpy==1.26.4" "einops==0.7.0"
```

### 6.3 编译带 CUDA 扩展的依赖

只有安装日志明确显示需要编译 CUDA 扩展时，才加载编译环境：

```bash
module load gcc-11.3
module load cuda-12.1
export CUDA_HOME=/storage/software/cuda-12.1

python -m pip install ninja packaging
python -m pip install -v 依赖包名
```

大型源码编译不能长时间占用登录节点，应写成作业脚本并通过 CPU 或 GPU 队列提交。

### 6.4 检查依赖冲突并记录环境

检查已安装包之间的依赖关系：

```bash
python -m pip check
```

查看关键包：

```bash
python -m pip show torch numpy tensorboard
```

项目环境确认可用后，可以记录精确版本：

```bash
python -m pip freeze > requirements.lock.txt
```

## 7. 在 GPU 节点验证完整环境

下面直接通过 `python -c` 在 GPU 节点检查 PyTorch 和 CUDA，不需要额外测试脚本。假设环境位于 `$HOME/venvs/dl-py310-cu121`：

```bash
PYTHON="$HOME/venvs/dl-py310-cu121/bin/python"
CHECK_CODE='import torch; print("PyTorch:", torch.__version__); print("PyTorch CUDA:", torch.version.cuda); print("CUDA available:", torch.cuda.is_available()); print("Number of devices:", torch.cuda.device_count()); assert torch.cuda.is_available()'

mkdir -p "$HOME/logs"
test -x "$PYTHON"

jsub -q gpu -J pytorch-check \
  -cwd "$HOME" \
  -o "$HOME/logs/pytorch-check.%J.out" \
  -e "$HOME/logs/pytorch-check.%J.err" \
  -n 2 -M 8192 \
  -gpgpu 1 \
  "$PYTHON" -c "$CHECK_CODE"
```

查看作业：

```bash
jjobs
```

查看最新日志：

```bash
ls -lt "$HOME/logs" | head
```

正常输出应包含：

```text
CUDA available: True
Number of devices: 1
```

更多作业查询、日志和排错命令见[高算平台作业调度系统命令手册](高算平台作业调度系统命令手册.md)。

## 8. 常见问题

### 8.1 安装到了错误的 Python 环境

```bash
which python
python --version
python -m pip --version
```

三个命令都应指向同一个环境。不要使用 `sudo pip install`，也不要直接使用 `/usr/bin/python`。

### 8.2 提示 No matching distribution found

常见原因：

- 当前 Python 版本不受该依赖支持；
- 指定版本不存在；
- `torch`、`torchvision`、`torchaudio` 版本不匹配；
- PyTorch CUDA wheel 使用了错误的索引地址。

查看清华 PyPI 镜像中的可用版本：

```bash
python -m pip index versions 包名
```

例如：

```bash
python -m pip index versions numpy
```

PyTorch CUDA wheel 应直接查询 PyTorch 官方安装页面。

### 8.3 配置后仍未使用清华镜像

环境变量的优先级可能高于 pip 配置。先检查：

```bash
env | grep -E '^PIP_(INDEX_URL|EXTRA_INDEX_URL)='
python -m pip config debug
```

如果环境变量指向其他源，可在当前终端取消后重试：

```bash
unset PIP_INDEX_URL PIP_EXTRA_INDEX_URL
python -m pip install -r requirements.txt
```

### 8.4 `torch.cuda.is_available()` 在 GPU 作业中仍为 False

依次检查：

```bash
python -c "import torch; print(torch.__version__); print(torch.version.cuda)"
nvidia-smi
```

同时确认：

- 作业提交到了 GPU 队列；
- `jsub` 命令包含 `-gpgpu 1`；
- 安装的不是 CPU-only PyTorch；
- PyTorch CUDA 运行时没有超过驱动支持范围；
- 作业使用的是目标环境的 Python 绝对路径。

### 8.5 编译 CUDA 扩展时找不到 nvcc

```bash
module load gcc-11.3
module load cuda-12.1
export CUDA_HOME=/storage/software/cuda-12.1

command -v nvcc
nvcc --version
```

### 8.6 恢复 PyPI 官方源

```bash
python -m pip config unset global.index-url
python -m pip config list
```
